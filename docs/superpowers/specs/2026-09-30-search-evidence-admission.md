# Search evidence admission (beta 0.2.4)

Approved product decisions (2026-09-30): With zero or one relevant usable document, do not deliver a full report; fail with `insufficient_relevant_evidence`, preserve accepted evidence and coverage, and invoke the existing failure/refund path where billing is active. Replace "已支持评论" with accurate searchable-public-web wording; Web Search excerpts are not verified comments.

Candidate → admission → storage → insight/report. Preserve `keywords`/`sources` public request in P0. The query engine is the only relevance decision owner; Go verifies admission protocol and source scope before persistence, not a second semantic classifier. Input is untrusted provider summary/snippet. Reject boilerplate, empty excerpts, and candidates without positive evidence. ASCII model/identifier tokens require complete boundaries; Chinese phrases match normalized text; whitespace-separated parts require all parts. This first version is deliberately conservative: ambiguous subjects and synonyms require future explicit context rather than guessed aliases. Per-keyword search semantics remain OR; fix UI max keywords to 8 and remove misleading one-word 'supplementary' tags pending explicit subject/qualifier semantics.

Admission must occur before returning/truncating accepted documents. Query response includes `admission_version` and structured coverage with candidate count, unusable count, irrelevant count, duplicate count, accepted count, per-keyword failures and bounded-result limitations. Missing/mismatched protocol fails closed, not interpreted as zero relevant. Coverage is persisted per analysis (additive JSONB), tenant scoped; old rows are `unknown` and not retroactively adjudicated. A successful provider request with <=1 relevant usable document is distinct from a provider/transport failure. Do not call insight/report in either case. Preserve accepted evidence and diagnostics on insufficiency; existing `markFailed` refunds where active. PG beta credit bypass is not live billing acceptance.

Topics must not depend on rejected documents. Topic `doc_ids` need to be verified against accepted IDs before persisting count/trend; no fabricated quote or source. History is immutable: existing rerun deletes old raw documents, so do not use rerun to bulk-correct old analyses. Rollout requires disposable PostgreSQL migration/contract test, snapshot/restart/idempotency and tenant isolation tests, build locally, read-only live diff, backup, narrow deployment, authenticated and provider smoke. No production operations as part of writing this spec.
