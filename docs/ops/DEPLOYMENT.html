部署指南

Ubuntu 24.04 · 无 Docker · 已装 Nginx · 单机部署 · 盘古舆情 v2.0

部署拓扑

# 单台服务器，全部进程由 systemd 守护
浏览器 ──HTTPS──▶ nginx (80/443)        ← 已存在，仅添加站点配置
                   ├── /          → /opt/pangu/web/dist    前端 React 静态文件
                   └── /api/*     → 127.0.0.1:8080        Go API (yuqing-server)

systemd 服务:
  yuqing-server    Go API 进程（无状态 HTTP + 内存 store）
  yuqing-worker    Go 后台进程（队列消费 + 定时任务）

数据采集链路:
  Go Worker → Python query_engine → Bocha API 搜索 → Scrapling 抓取正文
                                       ↑
                              PUT /admin/settings 更新 key（无需重启）

一键部署

1

获取代码

git clone https://github.com/jetchanxxx-tech/yuqing.git /opt/pangu-source
cd /opt/pangu-source
2

执行部署（幂等，可重复运行）

sudo YUQING_DOMAIN=your-domain.com \
     YUQING_JWT_SECRET=$(openssl rand -base64 32) \
     BOCHA_API_KEY=sk-YOUR-BOCHA-KEY \
     bash scripts/deploy.sh

首次约 3-8 分钟。输出中 [SKIP] 表示已有组件自动跳过。

3

访问验证

curl https://your-domain.com/api/v1/health
→ {"status":"ok"}
⚠ 首次部署后必须做：1) 部署脚本会自动配置 JWT secret 和 Bocha API key；2) 数据库迁移 CLI 占位期间需手工执行 migrations/platform/0001_init.sql。

手动分步部署

1. 系统依赖

# nginx 已存在 → 跳过
sudo apt-get install -y postgresql postgresql-contrib redis-server python3-venv python3-pip certbot python3-certbot-nginx

# Go ≥1.25
curl -fsSL https://go.dev/dl/go1.25.5.linux-amd64.tar.gz -o /tmp/go.tgz
sudo rm -rf /usr/local/go && sudo tar -C /usr/local -xzf /tmp/go.tgz

# Node ≥20.19 LTS
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo bash -
sudo apt-get install -y nodejs

2. 数据库

sudo -u postgres createdb yuqing_platform
sudo -u postgres psql -c "CREATE USER yuqing WITH PASSWORD 'yuqing' CREATEDB;"
sudo -u postgres psql -c "GRANT ALL ON DATABASE yuqing_platform TO yuqing;"
sudo -u postgres psql -d yuqing_platform -f platform/migrations/platform/0001_init.sql

3. 构建

cd platform && CGO_ENABLED=0 GOOS=linux go build -trimpath -ldflags="-s -w" -o /opt/pangu/bin/ ./cmd/...
cd ../web && npm ci && npm run build && cp -r dist /opt/pangu/web/

4. Python 引擎 + Scrapling

python3 -m venv /opt/pangu/engines/venv
source /opt/pangu/engines/venv/bin/activate
pip install -r engines/requirements.txt
scrapling install --chromium   # 首次 ~150MB 下载

5. 配置 + systemd + nginx（同 deploy.sh 处理）

cp platform/config.example.yaml /opt/pangu/config/config.yaml
sudo nano /opt/pangu/config/config.yaml       # 编辑 jwtSecret, db 密码
sudo cp scripts/systemd/*.service /etc/systemd/system/
sudo useradd -r -m -d /opt/pangu -s /usr/sbin/nologin yuqing
sudo systemctl daemon-reload && sudo systemctl enable --now yuqing-server yuqing-worker
sudo cp scripts/nginx.conf /etc/nginx/conf.d/yuqing.conf
sudo nginx -t && sudo systemctl reload nginx

配置说明

配置项说明必改
auth.jwtSecretJWT 签名密钥，至少 32 字符随机串✅ 是
db.primary平台库连接串（含 yuqing 用户密码）✅ 是
dataSources.bochaApiKeyBocha AI 搜索 API key（环境变量 BOCHA_API_KEY 优先）✅ 是（可后台配置）
server.addrAPI 监听地址（nginx 反代目标，保持 :8080）否
queue.drivermemory / redis / rabbitmq / nats单机用 memory
llm.models[].apiKey大模型 API key（联调阶段填）暂不需要
storage.driverlocal / s3单机用 local

Bocha API Key 配置

两种方式设置 Bocha API key（搜索+采集链路必需）：

方式一：部署时环境变量（推荐）

sudo BOCHA_API_KEY=sk-YOUR-BOCHA-KEY bash scripts/deploy.sh

方式二：Admin 后台在线更新（零重启）

curl -X PUT https://your-domain.com/api/v1/admin/settings \
  -H "Authorization: Bearer <admin_token>" \
  -H "Content-Type: application/json" \
  -d '{"bocha_api_key":"sk-YOUR-BOCHA-KEY"}'

更新后下一个分析任务立即使用新 key，无需重启任何服务。

Scrapling 安装验证

# 验证 Scrapling 可正常抓取
cd /opt/pangu
source engines/venv/bin/activate
python3 -c "
from scrapling.fetchers import Fetcher
page = Fetcher.get('https://httpbin.org/html', timeout=10)
print('Title:', page.css('title::text').get())
print('✓ Scrapling OK')
"
如果输出 ✓ Scrapling OK，说明数据采集链路就绪。如果报错，检查：scrapling install --chromium 是否执行，BOCHA_API_KEY 是否设置。

systemd 管理

# 状态与日志
systemctl status yuqing-server
journalctl -u yuqing-server -f          # 实时日志（slog JSON）
journalctl -u yuqing-worker -f

# 启停
systemctl restart yuqing-server yuqing-worker

# 配置变更后重启
sudo nano /opt/pangu/config/config.yaml
systemctl restart yuqing-server yuqing-worker

与已有 Nginx 共存

脚本不安装、不重装已有 nginx，只新增 /etc/nginx/conf.d/yuqing.conf。如果同域名已有其他站点，通过 server_name 区分虚拟主机，nginx 自动按 SNI 分流。

常见问题

Q: 部署后注册的用户重启就没了？

MVP 用内存 store。生产数据持久化需接 PostgreSQL store（接口已预留，替换实现即可）。

Q: 为什么搜不到真实数据？

检查 Bocha API key 是否配置（GET /admin/settings），Scrapling 是否安装（python -c "from scrapling.fetchers import Fetcher"）。

Q: 部署脚本重复运行安全吗？

安全。所有组件安装前检测（[SKIP]），配置文件/数据库/nginx 站点已存在绝不覆盖。

Q: nginx 已被其他项目占用？

无冲突。脚本只新增 conf.d/yuqing.conf，通过 server_name 区分虚拟主机。

Q: 数据库迁移为什么报占位提示？

yuqing-cli migrate 当前为占位实现。手工执行 migrations/platform/0001_init.sql。goose 接线在遗留清单中。

Q: 怎么更新 Bocha API key？

管理员通过 Admin 面板或 API 直接 PUT /api/v1/admin/settings，无需重启服务。
