盘古舆情 · CI/CD 体系规划

更新：2026-10-09 · GitHub 构建配置与分支执行约定。工作流结果、默认分支和保护规则以 GitHub 实际状态为准；本文件不代表 CI 已通过或自动部署已启用。生产 E2E、密钥扫描与自动 CD 仍按各阶段说明规划。

强制规则：所有编译、构建和编译型测试只在 GitHub 托管 runner 执行。本地电脑、开发主机和任何自有服务器禁止 go build、go test（含 -race / -c）、go vet、go run、npm run build、tsc、Vite 打包及其脚本封装；RSSHub 等附属服务也适用。禁止 self-hosted runner 构建。此规则替代 2026-09-13 规划中的本地构建与服务器测试方案。

约束对 CI/CD 的影响

分支职责与发布产物

分支职责产物用途

二、总体流水线设计

构建和 PostgreSQL 测试在 GitHub 托管 runner 上执行；部署使用已通过检查的同一提交产物：

代码提交（push / PR）
  │
  ├─ 门禁 1【build-release.yml】Go 全量 -race 测试 + vet + 三二进制 + 前端 lint/build
  ├─ 门禁 2【postgresql 作业】workflow_call 复用 postgresql-tests.yml → 真实 PG 契约测试
  ├─ 规划扩展【Python / 密钥扫描 / 生产 E2E】按阶段实施，不能视为已有成功检查
  │
  └─ package（needs: go / frontend / postgresql；三类检查全部成功）
       → Actions artifact（提交 SHA，保留 30 天）
       → 本地下载校验并上传（不编译）
       → 服务器验哈希 / 解包 / 备份 / 配置 / 迁移 / 安装产物 / 启停 / 健康检查
部署前必须核对目标 prod SHA 的构建与 PG 测试均成功。CI 配置存在不等于已通过；自动 CD 和额外门禁不能仅凭规划文档视为已启用。

三、分阶段实施计划

阶段 1CI 基础门禁（预计 0.5 天，风险低）

文件：.github/workflows/build-release.yml；触发：push 到 dev / prod / main / beta/**、PR 及手动 workflow_dispatch。全部使用 GitHub 托管 runner。

Job步骤说明
Go 检查与构建checkout → setup-go → go test ./... -count=1 -race → go vet ./... → linux/amd64 构建生成 yuqing-server、yuqing-worker、yuqing-cli；仅 GitHub runner 执行
前端setup-node 22 → npm ci → npm run lint → npm run buildoxlint + tsc + vite，仅 GitHub runner 执行
部署包Go、前端、PostgreSQL 全部成功 → 收集源码、platform/bin、web/dist → SHA256SUMS → tar.gz → actions/upload-artifactyuqing-linux-amd64-${SHA}.tar.gz 与外部 .tar.gz.sha256；带提交 SHA，保留 30 天。PG 失败不生成归档
Python（规划扩展）setup-python 3.11 → 依赖 → python -m pytest engines/tests/单独确认工作流与结果后才能算作发布门禁
密钥扫描（规划扩展）gitleaks/github-action（或 secretlint）公开仓库凭据检查；不得宣称尚未实施的扫描已通过

阶段 2PG 集成测试（预计 0.5 天）

build-release.yml 的 postgresql 作业通过 uses: ./.github/workflows/postgresql-tests.yml 调用现有 PG 工作流（workflow_call）。因此 dev / prod / beta/** 的构建自动包含 PG 检查；原 PG 工作流保留 main / develop 的独立 push/PR 触发，并支持手动触发。最终 package 依赖 go、frontend、postgresql 全部成功。用 GitHub 的 services: postgres:15 起库，以下是原理示例，实际步骤以工作流文件为准：

pg-contract:
  services:
    postgres:
      image: postgres:15
      env: { POSTGRES_USER: yuqing, POSTGRES_PASSWORD: test, POSTGRES_DB: yuqing_test }
  env:
    YUQING_TEST_PG_URL: postgres://yuqing:test@localhost:5432/yuqing_test?sslmode=disable
  steps:
    - run: |
        sudo apt-get install -y postgresql-contrib   # 提供 citext 扩展
        psql ... -c 'CREATE EXTENSION IF NOT EXISTS citext'
    - run: go test ./... -count=1
历史上曾在服务器人工执行 PG 契约测试；今后只在 GitHub 托管 runner 执行。部署前查看目标提交的 PG 工作流结果，不在服务器补跑 go test。

阶段 3生产 E2E 门禁（预计 0.5 天）

  • 规划文件 .github/workflows/e2e.yml，触发：push 到 prod + 每日 cron（建议 02:17 避开整点）+ 手动 workflow_dispatch；在 GitHub 托管 runner 上执行。
  • Secrets：E2E_EMAIL / E2E_PASSWORD（生产测试账号）→ 以环境变量注入，沿用现有 spec 的「无凭据即抛错」设计。
  • 步骤：checkout → setup-node → npx playwright install --with-deps chromium → E2E_EMAIL=... E2E_PASSWORD=... npx playwright test --config e2e/production.config.ts。
  • 失败策略：邮件/issue 告警；不自动回滚（E2E 失败先人工判断是功能回归还是数据/凭据问题）。

阶段 4使用 GitHub 产物发布（自动 CD 另行规划）

当前发布约定：GitHub 完成全部构建与编译型测试，本地下载、校验和上传已构建产物，生产只安装。不得使用 self-hosted runner 编译，也不得在缺少产物时从源码自动构建。

位置允许操作产物与门禁
GitHub 托管 runnerGo/前端/RSSHub 构建、编译型测试、打包同一提交 SHA 的源码与产物；构建、PG 测试均成功
本地或开发主机编辑、轻量语法检查、下载、校验、上传核对 workflow run ID、prod SHA 与归档 SHA256；不编译
生产服务器验哈希、解包、配置、备份、迁移、安装、启停、健康检查sha256sum -c SHA256SUMS；缺产物立即终止
dev → prod PR（检查与评审通过）
  → 合并后 prod SHA 的 GitHub 构建与 PG 测试成功
  → 下载 yuqing-linux-amd64-${SHA}.tar.gz 与 .tar.gz.sha256
  → 本地 sha256sum -c 归档校验文件 → 上传 root@101.96.209.90:22352
  → 服务器再次校验归档 → 解包 → sha256sum -c SHA256SUMS
  → 备份 → 停止写入 → 新 CLI 迁移 → 安装二进制/前端/引擎源码
  → 启动服务 → 健康检查与页面验收
  → 失败时恢复已备份的产物；迁移回滚按数据库备份方案执行
产物保留 30 天，过期后在 GitHub 重跑目标 SHA 构建。RSSHub 更新需要另备 GitHub 构建的运行时包；当前项目部署包不包含 RSSHub。将来自动 CD 也只能消费已验证产物，不触发服务器编译。

仓库公开：CI 配置文件本身也要过密钥扫描门禁；secrets 只能以 ${{ secrets.X }} 引用，禁止 echo/printenv 输出。

五、回滚与可观测

  • 回滚：部署前备份旧二进制、dist、源码及数据库；失败恢复已验证的快照或旧 SHA 的 GitHub 产物。不得 checkout 旧代码后在本地或服务器重新编译。自动回滚是否可用须单独验证。
  • 部署痕迹：记录分支、完整提交 SHA、工作流 run ID、归档及文件 SHA256，与服务器部署日志对应；禁止输出凭据。
  • 自检闭环：healthcheck.sh 作为部署最后门禁，页面验收另行确认；自动定时巡检仍属规划。
  • 告警（规划）：未来 E2E nightly 失败可创建 GitHub issue，自动去重；实施后再确认结果。
