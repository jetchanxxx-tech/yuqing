一、项目代码与部署过程

代码仓库

项目盘古舆情（yuqing）

默认分支main

仓库公开：Bocha/DeepSeek key 只允许存在于服务器 engines.env（chmod 600）与本地 credentials.local.md（已 gitignore）。任何提交前自查 git diff --cached | grep 'sk-'。

部署过程（幂等，可反复执行）

# ① 服务器取源码（GitHub 从境内服务器不可达时，用本地打包 + SCP：
#    git archive --prefix=pangu-src/ HEAD | gzip > pangu-src.tar.gz，上传解压到 /opt/pangu-source）
# ② 执行部署（已装组件自动 [SKIP]，已有配置绝不覆盖）：
sudo YUQING_DOMAIN=yuqing.pangu-cloud.com bash /opt/pangu-source/scripts/deploy.sh

# ③ 首次部署后（或 config 变更后）跑数据库迁移：
cd /opt/yuqing
YUQING_CONFIG=/opt/yuqing/config/config.yaml bin/yuqing-cli migrate platform

# ④ 自检：
sudo bash /opt/pangu-source/scripts/healthcheck.sh

deploy.sh 内部流程：系统依赖检测（nginx/postgresql/redis/go/node/python3-venv）→ 系统用户 yuqing + 数据库 yuqing_platform → 交叉编译 Go 三二进制 → 前端 npm build → Python 引擎 venv + Scrapling → 生成 config.yaml（已存在则跳过）→ 注册 systemd units → 引擎环境变量 → nginx 站点（有域名走 HTTPS + acme.sh）→ 健康检查。旧命名（yuging-*）遗留服务会被自动清理。

环境变量：YUQING_DOMAIN（站点域名）、YUQING_ROOT（安装根目录，默认 /opt/yuqing）、YUQING_DB_PASSWORD、YUQING_BOOTSTRAP_ADMIN_EMAIL（引导管理员，已写入 drop-in）。

五、配置文件路径与参数说明

5.1 主配置 /opt/yuqing/config/config.yaml

键默认说明
server.addr:8080API 监听地址
db.primarypostgres://yuqing:***@localhost:5432/yuqing_platform?sslmode=disable平台库 DSN（含读写分离 replica 配置位）
store.drivermemorymemory | postgres。生产必须 postgres（重启不丢数据）；切 postgres 前先 yuqing-cli migrate platform
queue.drivermemorymemory | redis | rabbitmq | nats（远程队列接入后管线可搬回 worker）
engines.query.urlhttp://localhost:8000采集引擎地址；为空时管线不启动，任务停在 queued
engines.insight.urlhttp://localhost:8002分析引擎；为空时分析步骤降级（任务仍完成 + warning）
engines.report.urlhttp://localhost:8003报告引擎；为空时报告降级
engines.*.timeout60s-300s各阶段超时；管线总预算 = 已接线引擎超时之和
auth.jwtSecret—JWT 密钥（部署时生成，勿改 —— 改后全部 token 失效）
llm.models[]deepseek-chat 等LLM 定价目录（平台成本/用户售价 per 1M tokens）
config.yaml 由 deploy.sh 首次生成后绝不覆盖；升级新参数请手工 diff /opt/pangu-source/platform/config.example.yaml。

5.2 引擎密钥 /opt/yuqing/config/engines.env（chmod 600）

BOCHA_API_KEY=sk-...          ← 数据采集（搜索发现）
DEEPSEEK_API_KEY=sk-...       ← 情感/话题/报告（LLM）

三级来源：环境变量 → 平台 settings（管理后台「数据源配置」在线改，存 PG，重启不丢）→ 请求参数。改 engines.env 后 systemctl restart yuqing-{query,insight,report} yuqing-server。

5.3 systemd 与 nginx

路径说明
/etc/systemd/system/yuqing-*.service7 个 unit：server 的 Environment=YUQING_CONFIG=/opt/yuqing/config/config.yaml；引擎的 WorkingDirectory=/opt/pangu-source、PYTHONPATH=/opt/pangu-source、EnvironmentFile=-/opt/yuqing/config/engines.env
/etc/systemd/system/yuqing-server.service.d/bootstrap-admin.conf引导管理员：YUQING_BOOTSTRAP_ADMIN_EMAIL=admin@pangu.com（该邮箱注册即 platform_admin）
/etc/nginx/conf.d/yuqing.conf站点：443 ssl（acme.sh 证书）+ /.well-known/acme-challenge/ 直通 + /api 反代 8080（SSE 已关 buffering）+ 静态 dist

六、服务重启

# 全部重启（顺序：引擎 → server；或一次性 restart）
systemctl restart yuqing-query yuqing-media yuqing-insight yuqing-report yuqing-forum
systemctl restart yuqing-server yuqing-worker

# 单个
systemctl restart yuqing-insight

# 查看状态
systemctl status yuqing-server
systemctl is-active yuqing-query yuqing-media yuqing-insight yuqing-report yuqing-forum

# 开机自启（已 enable）
systemctl is-enabled yuqing-server
unit 已配 Restart=always + RestartSec=5：进程崩溃自动拉起。更新代码后必须 restart（uvicorn 无热重载，Go 二进制同理）。
重启 yuqing-server 会丢失 PGMeter 进程内配额（需注册/登录触发 SetQuota 重新下发）；账号/任务/文档数据在 PG，不受影响。

八、自检与自启

8.1 自检脚本 scripts/healthcheck.sh（已入库）

sudo bash /opt/pangu-source/scripts/healthcheck.sh            # 交互输出全部检查项
sudo bash /opt/pangu-source/scripts/healthcheck.sh --json     # JSON（监控采集）

检查项：7 个 systemd 服务 active、Go API /health、5 个引擎 /health、PostgreSQL、Redis、nginx 配置、HTTPS 站点、磁盘空间（<1GB 告警）。退出码 0=正常 1=异常。

8.2 自启（已内置）

  • 全部 unit Restart=always：进程崩溃 5 秒自动拉起；enable 后开机自启。
  • acme.sh cron：每日检查证书，到期前 30 天自动续期 + reload nginx。

8.3 推荐：systemd timer 定时自检（5 分钟一次，异常记录日志）

# /etc/systemd/system/yuqing-healthcheck.service
[Unit]
Description=yuqing healthcheck
[Service]
Type=oneshot
ExecStart=/opt/pangu-source/scripts/healthcheck.sh --json

# /etc/systemd/system/yuqing-healthcheck.timer
[Unit]
Description=Run yuqing healthcheck every 5 min
[Timer]
OnBootSec=2min
OnUnitActiveSec=5min
[Install]
WantedBy=timers.target

systemctl enable --now yuqing-healthcheck.timer
# 查看结果: journalctl -u yuqing-healthcheck.service | tail

8.4 手工健康快查

curl -s http://127.0.0.1:8080/api/v1/health

十、用户中心运维（v0.1.1-beta，2026-09-22 上线）

10.1 通知服务配置（管理后台 → 通知服务 Tab）

用户中心邮件（验证/改密）与短信（手机绑定）的供应商凭据用户自备（供应商账号实名与签名/模板报备由使用者办理）。admin 在「通知服务」Tab 在线填写，存 platform_settings 表，保存即时生效、无需重启。配置键在迁移 0007 已 seed（空值占位），后台只需填值。

通道供应商配置键（platform_settings）
邮件Resendemail_provider=resend、resend_api_key、email_from_address（必填）、email_from_name
SMTPemail_provider=smtp、smtp_host / smtp_port（缺省 465）/ smtp_username / smtp_password、email_from_address（必填）
短信阿里云 / 腾讯云sms_provider=aliyun|tencent、sms_access_key_id / sms_access_key_secret（腾讯云对应 SecretId/SecretKey）、sms_sign_name、sms_template_code；腾讯云另需 sms_sdk_app_id
未配置 = fail-closed：发码接口直接报错 mail: email_from_address not configured (admin settings) / sms: sms_provider not configured (admin settings)，不会静默吞码。排查用户「收不到验证码」第一步：看后台通知服务是否已配置、供应商侧余额与签名/模板状态。

10.2 防刷机制

机制阈值表现
发码节流同一目标（邮箱/手机号）60 秒一次超频 HTTP 429（QUOTA_EXCEEDED，提示稍候再试）
验证码防穷举单个验证码错误 5 次作废第 5 次错码后验证码立即作废，此后即使提交正确码也 404（too many attempts, code invalidated），须重新发码

10.3 trial_analysis_used 字段语义

方案 B 试用机制：邮箱未验证的用户允许试用 1 次分析。额度记录在 users.trial_analysis_used，消费时原子扣减（0→1，UPDATE 带 WHERE COALESCE(trial_analysis_used,0)=0 条件，单条 SQL 竞态安全），用完即止、无恢复机制。
