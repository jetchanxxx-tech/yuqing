本表完整记录本计划台账的 Ruling（含重复门禁条目的独立含义），说明原因与判断错误的代价。它不增加未验证功能的通过声明。

#决定原因限制或代价
1新 run 使用 semantic-v2，历史 lexical 仅保留读取完成已批准架构，不把旧 fixture 或无模型检索当验收。新资料不足时继续拒绝完整报告，需要补材料。
2依已批准计划分工；本轮执行由主控完成，审查只读各自文件所有权与全量集成验证保持，避免互相回退。潜在接口问题须由集成契约和真实链路发现。
3候选保存文本按 run 存 PostgreSQL保留内容哈希、复合身份 FK；注销沿现有保留决定清理证据，财务身份保留。增加数据库存储，不能绕过既有保留规则。
4100 条标准为合成参考，用户确认既有标签不伪装为原始人工采集或真实文章标准，供应商复测另记。固定集分布有限，不可推广为全网准确率。
5局部静态审查不替代托管、真实模型和生产验收每一阶段保留独立门禁；当前精确 prod 八项与真实链路均已实测。任一门禁失败阻止发布，不能选旧绿结果掩盖失败。
6无编号旧响应继续原严格原文/来源校验保持已有响应兼容；编号字段存在但无效时禁止旧文本救援。旧供应商仍可能因引文重写失败，但不会放行不实引用。
7精确 head 的 hosted 与真实文章/完整报告分开判断固定集、隔离环境、生产三份证据范围明确。本次逐字/出处核对不等于文章级准确率评估。
8制品、迁移、备份与生产状态必须实际核验prod 精确 SHA 的正式包、恢复库、停写备份与公网检查均已完成。静态批准不能替代这些检查，未通过即不开放。
9未改动的来源/日期/SSRF/计费架构沿用既有审查本轮检查变化的引用/纠正/导出路径，并由全量真实 PG/桥接验证集成。先前潜在缺陷仍需后续复现并向前修复。
10任意叙述保持模型研判范围确定性验证针对结构化引语、风险和来源位置，不新增全面事实核查。对未经独立确认的叙述需保留人的判断。
11验收只允许精确已知的材料范围提示analysis.warning 的固定公开网页/摘要范围提示保留；洞察/报告失败警告与未处理仍阻断完成。新增未知提示必须调查，不能通用忽略 warning。
12日期按同一时间点比较API PG 序列化成 Z，报告保留 +08:00；继续严格检查中国日期窗口和原 date_sources。无时区或确有不一致不能当等价通过。
13独立浏览器容器在本地校验，服务器验证包内同一 payload311 个文件已做独立/部署包等价对照，服务器完整归档和 manifest 绑定同一字节；减少重复传输。没有声称在服务器再次校验独立容器，任何包内差异均被摘要与启动探针拦下。
