1. 核查结论

五个研判维度有实质性提示词；四种业务视角与六类场景模板尚未形成对应的专项提示词。 当前的场景模板只是预选分析类型。不能把页面上有一个模板名称，解释为模型已经执行了该场景的专门方法。

本报告根据工作区源码与 2026-10-15 获取的智谱官方文档整理。未读取密钥、未调用付费模型、未执行构建、未部署。本地 Git 的 worktree 指针引用 Windows 路径，无法在此环境解析提交 SHA；下文以源码路径及 SHA-256 固定本次核查依据。线上实际模型、端点配置和已部署版本未在本次验证。

对象当前事实是否有独立实质性 Prompt
五维研判每维有独立人设、任务与一次模型调用；完整模式五维，速览模式热度／情感／深层原因三维有
四种业务视角event / brand / competitor / industry 被作为字符串写入维度 Prompt 和摘要上下文；没有对应专属任务映射没有专项 Prompt
六类场景模板场景卡片只设置 defaultType；新建分析只提交名称、analysis_type、关键词、来源与日期没有场景专项 Prompt
监测方案目录保存模板标识、版本和默认视角，配置预览／草稿存在；不是 Prompt 注册表没有自定义 Prompt 字段
日报／周报／事件报告模板template_id 控制部分章节展示；写作调用仍使用同一个 _LLM_PROMPT，未将 template_id 注入写作要求共用写作 Prompt
Forum 多 Agent四专家与主持人各三轮，共 15 个文本模板；独立 glm-4-flash 客户端有，但常规分析管线未发现接线

维度人设原文任务原文
背景与事件概述（background）你是舆情事件溯源专家，擅长从碎片信息中还原事件全貌与因果链。梳理事件起因、发展脉络与关键节点；标出时间线上真正被反复提及的转折点，而不是罗列所有日期。
热度与传播路径（heat）你是传播学研究者，擅长还原信息如何从源头扩散到大众视野。分析传播路径、平台分布、引爆点与关键传播角色；区分原始信源与二次转载，指出哪条内容真正带动了扩散。
公众情感与观点（sentiment）你是民意研究专家，关注普通人的真实情绪而非抽象概括。梳理情感倾向分布、观点阵营与争议焦点；捕捉网民的真实表达方式（口语、梗、情绪词），而不是把它们翻译成书面语。
群体与平台差异（group）你是社会分层研究者，擅长发现不同群体对同一事件的态度分歧。对比不同平台/群体的立场与话语差异；指出被主流叙事忽略的声音，以及同一事实在不同平台上被如何不同地表述。
深层原因与社会影响（deep_cause）你是社会观察家，擅长穿透表象追问结构性动因。追问根本原因、社会心理与长期影响；指出该事件折射出的更大议题，而不是停在事件本身。

共同骨架：核心发现 → 数据 → 代表性声音 → 深入解读 → 趋势。要求 findings 至少 150 字、deep_read 至少 100 字、至少三条带数字的数据点、至少两条逐字原声；素材不足须说明。引用有原文子串校验和重试。当前引语结构只有 text/source，校验是“命中任一文档”，尚未绑定指定 document_id 与该条来源。

每维 temperature=0.6、max_tokens=8192，分类与维度共享最多三路并发。每篇正文最多 3000 字，维度素材包预算 16000 字符，按最新优先截取。字数与条数要求主要在 Prompt 内表达，不能直接视为代码已强制验证的质量保证。

6. 自定义模板可行性与建议方案

可行，但当前尚无保存、传递和执行用户 Prompt 的完整接口。现有 DimensionSpec、统一 LLM 客户端、维度 JSON 结果和列表渲染可以复用；Go 请求契约、任务／运行快照、PG 存储和前端 API 需要扩展。作为与租户业务关联的能力，模板与运行记录应进入业务层，供应商调用由已有 adapter 与组合根装配。

建议先建立四视角＋六场景的内置 Prompt 注册表，再开放“复制内置模板 → 编辑 → 试运行 → 保存版本”。首期编辑分析目标、关注问题、维度任务、输出语气与篇幅；高级模式可补充 Prompt 文本，但保持固定 JSON 契约、证据校验、租户授权、套餐维度／预算约束。

  1. 组成：平台事实与证据规则＋共同输出契约＋不可变素材包＋业务视角任务＋场景任务＋维度任务＋用户补充要求。把长期稳定且相同的部分放前面，把本次差异放后面；自定义要求不能改变访问权限或执行范围。
  2. 持久化：模板 ULID、租户与所有者、名称、基础场景／视角、维度说明、版本和内容哈希。每次运行保存实际 Prompt 快照、模型、参数、材料哈希／准入版本；改模板不改历史报告。
  3. 试运行：展示本次选定维度、将使用的材料、预计 token 上限与试运行是否消耗分析额度。实际用量、供应商成本与失败／重试记录仍由统一桥接记录；不得用估算代替账务事实。
  4. 执行：只传服务端解析出的已授权模板版本。用户不能通过 Prompt 设置 API Key、任意请求端点、跨租户材料或无限工具调用；工具循环有最大轮数、时间和用量上限。
  5. 验收：用同一固定语料比较不同场景／自定义版本，检查确有内容差异、引用与数值可追溯、未知信息明确、重跑历史不变、越权被拒绝。需要通过真实入口和 GitHub 托管检查；本文未执行这些验收。

7. 智谱 API 能力与项目优化

共享客户端代码默认 https://open.bigmodel.cn/api/paas/v4、glm-5.3-flash；后台设置、请求参数和环境变量可覆盖，因此不能把代码默认值视为线上实际配置。已有 chat/completions、JSON 模式、供应商流式协议、实际 usage／缓存 token 记录。客户端目前将整段 SSE 收集后再解析，前端看到的是任务状态推送，不是模型逐 token 输出。

能力与优先级现状／官方事实本项目用途与条件
推理强度：先修正源码 quick 传 thinking.type=low；官方 ChatThinking type 只支持 enabled/disabled，5.3-Flash 只能 enabled；强度单独通过 reasoning_effort 设置。400 后源码会去掉该参数重试。建议 enabled＋reasoning_effort=low 用于速览／分类，复杂因果或冲突证据用 high；未验证实际端点前不能宣布 low 生效。比较耗时、输出 token、完整率与质量。
上下文缓存：近期官方提供隐式前缀缓存，长相同前缀更容易命中；建议至少 500 tokens。源码已有 cached_tokens 记录，但不同维度人设／任务置于素材前。固定输出规范和同一批证据置于共同前缀，维度差异放后；保留差异任务。并发首次调用不保证命中，按实际缓存 token 验证。计价还需缓存专门价格。
结构化输出：近期强化已用 response_format=json_object；官方文档示例的 Schema 验证在应用端执行，未核实 json_schema／strict 服务端保证。补 Pydantic／Schema、枚举、文档 ID、字段完整性验证；数字来自代码聚合，引用绑定文档与来源，明确事实／推断／未知。不要把 JSON 合法等同内容真实。
联网搜索：中期Web Search API 返回标题、URL、摘要；有自研、搜狗与夸克引擎，可限域名和相对时间范围。独立 API 文档未见任意起止日期字段。作为 Bocha 的补充／故障回退；用于找官方回应、补齐证据与交叉核验。仍走准入、去重、来源与日期检查，不能直接用搜索生成答案代替落库证据。公众号／短视频覆盖需分别实测。
语义向量＋Rerank：中期提供 Embedding-3 与 rerank；当前查询路径主要关键词、来源／时间过滤和 URL／内容哈希去重。解决品牌别名、歧义、无关同名结果与转载近似重复；按维度选证据时保留反方和原始出处。先用人工标注样本校准阈值，不能只靠高相似度断言同一主体。
原生图片／视频理解：中期产品价值高当前默认 5.3-Flash 官方支持图片、视频、文件；项目 media_engine 仍返回预置 Mock。获得真实可访问素材后，做投诉截图、海报信息、视频关键帧与字幕证据；音频另可评估 GLM-ASR。绑定 URL／时间戳与素材权限；不把模型能读视频等同可抓取全平台视频和评论。
Function Calling：后续官方支持工具调用；现有客户端解析只保留 content，未实现 tool_calls 执行循环。提供只读本租户 search_documents/get_document/get_stats 等证据工具，支持追问与补证；按实际模型要求处理会话／推理字段，不把内部 reasoning 作为用户可见结论。需要工具适配与统一计量。
Batch：后续离线任务官方用于非实时批处理，支持模型可享折扣；需另验当前模型兼容范围。适合历史情感回填和离线模板评测；当前项目未接周期调度，不能称已可做自动日报，也不适合即时危机分析。

成本核查：2026-10-15 官方标准 API 价目列出 5.3-Flash 输入 0.8 元／百万 tokens、输出 2.8 元／百万 tokens、缓存命中 0.23 元／百万 tokens；该值是公开标价，不是本项目实际账单，实际端点／代理／协议价格需确认。现有 call_service 的价格快照只有 Input、Output，成本按全部 prompt_tokens×Input＋completion_tokens×Output 计算，尚未区分缓存优惠，记录 cache_tokens 不等于按缓存价格结算。新增能力也必须补对应费用单位和核验版本，缺价格或供应商 usage 时保留 pending／unknown，不能写零成本。

建议顺序：修正推理参数并完善证据／结构验证 → 补齐四视角六场景专项 Prompt → 提供版本化自定义模板 → 评估缓存与检索排序 → 接真实图像／视频材料 → 证据工具问答／离线 Batch。不要先靠更换更大模型掩盖模板未执行和输入证据不足。
