目标和边界

同一任务中的多个关键词被视为一个研究主题。材料可以只出现系列中的一个型号或关注点的同义表达，但必须由模型结合主题和原文证据判断。系统逐平台检索、按界限补抓正文、验证来源和日期，再进行有计量的语义准入。

本版本不做自定义模板、开放式多轮 Agent、模型路由、缓存、自动重跑旧任务或第三阶段优化。历史 lexical-v1 任务保持原审计事实；新 run 使用 semantic-v2。

验收标准

领域必须观察到的结果阻断条件
主题理解iPhone18/iPhone18 Pro/iPhone18 Max 中只出现一个型号的真实材料可判 direct；其他品牌仅命中泛词被判 irrelevant；对象与关注点同义表达可被识别。要求每个词面全部出现，或泛词误召回进入 direct。
平台覆盖每个选定平台有独立查询、候选、抓取、准入计数；混选不会把全部结果贴成第一个平台；未查询/失败与无相关材料分开。只发一次混合查询、来源标签来自请求顺序、平台失败被伪装为零结果。
正文补抓摘要为页面壳时尝试一次有界 Scrapling；正文清洗去除脚本/样式/导航；静态 15 秒、动态 25,000 毫秒、8 MiB/200,000 字符上限、取消后无后台抓取。把页面壳当证据、使用未验证的浏览器参数、超时后进程残留或把视频页面称作转写。
硬边界最终 URL、来源平台、公网地址、排除词和发布日期在模型前校验；越界/冲突/无法核验日期只留候选审计。LLM 以理由覆盖硬边界，或用抓取时间替代原始发布日期。
语义协议每份材料恰好一条 direct/context/irrelevant/uncertain 决策；ID、逐字证据、平台和日期均可回溯；非法 JSON/ID/引语 fail closed。缺失决策默认通过，引用跨文档拼接，或模型结果无法绑定真实材料。

预算和计量主题规划、query/relevance、洞察、报告均有 run_id、授权、持久 outbox、实际用量/失败状态；输出初始目标 16,384，截断只在剩余时限内重试一次至 32,768。无 run_id 直连供应商、丢失 ACK 删除 outbox、通过降低 max_tokens 隐藏超时。

RED → GREEN 证据

  1. 先提交失败测试：Python 主题边界/平台隔离/Scrapling fixture/语义协议，Go transport/pipeline/PG 并发与回滚，React/Playwright 状态与来源展示。
  2. 在 GitHub-hosted runner 上确认 RED；本地不得执行 Go build/test/vet、npm build/tsc 或依赖编译。
  3. 按 workstream ownership 实施最小改动，逐任务在 hosted runner 变绿；证据必须包含测试名称、提交 SHA、workflow run ID 和日志摘要。
  4. 人工标注集至少 30 direct、20 context、30 irrelevant、20 uncertain。发布集 direct precision ≥95%、recall ≥90%；来源/日期/引用越权放行必须为 0。展示误判样本，不用被测模型生成标签。
  5. 真实对账使用专用测试任务：至少一个系列任一型号入选、一个关注点不逐字出现但有原文依据的材料入选，并记录每个选定平台的候选/正文/准入/未处理计数。不能修改用户历史任务或伪造结果。

Hosted CI 门禁

  • build-release.yml：Go race tests/vet/三个 linux/amd64 二进制、Python 全量测试、前端 lint/build、Playwright。
  • postgresql-tests.yml：最新迁移、store 重建、租户隔离、并发/回滚、billing usage outbox 与旧 lexical-v1 数据读取。
  • 必须核对同一提交 SHA 的所有 job 为 success；跳过 PG、缺浏览器 fixture、失败的真实 Bocha/LLM 对账或未达到人工标注阈值均阻断发布。
  • 构建包必须通过外部归档 .sha256、BUILD_COMMIT 和解包后的 SHA256SUMS；浏览器产物也要有固定版本和哈希。

部署与回滚

  1. 在 dev 完成评审后创建 dev → prod PR；合并后只使用精确 prod SHA 的成功产物。
  2. 服务器先保存源码、配置、二进制和前端回滚包，再停止写入服务并备份 PostgreSQL，校验归档和 SHA256SUMS，解包到带 SHA 的 release 目录。
  3. 先用同一构建包内的 CLI 执行迁移和 schema 校验，再原子安装二进制/哈希前端、启动服务并执行健康检查。缺产物时立即失败，服务器不编译。
  4. 部署后运行专用真实 smoke：Bocha、至少两个所选平台、Scrapling 正文/摘要回退、语义 direct/context、报告文档 ID 和 usage 事件。保留 JSON/HTML 证据。
  5. 任一门禁失败：停止新服务，恢复上一份已验证 release/config，按数据库备份程序处理不可逆迁移；保留失败 SHA 和日志，不强制回滚数据库结构或覆盖用户数据。
