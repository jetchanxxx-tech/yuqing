报告专项失败

  1. 历史内容不稳定：创建两个报告版本后，按旧报告 ID 下载，返回了第二版内容。报告记录关联分析 ID，但被测下载路径从分析当前的 report_content 读取，没有按报告版本保存独立内容。风险是历史报告链接会静默改变内容。
  2. 格式菜单与报告记录不匹配：报告中心对每一行都提供 HTML、Markdown、PDF、Word 操作；当前记录格式为 HTML，尝试其他格式均返回 HTTP 409 “report is a html report, not …”。Pro 权限已放行，因此失败来自格式/记录契约，而非套餐门禁。
  3. Go Word 传输缺少输入：为定位原生 Word 流式端点，测试创建了一个 Word 格式记录。接口返回 HTTP 500；记录到 Go 发往 Python 的请求中 documents 和 context_documents 为 null，维度、日期范围和场景也缺失。下游 FastAPI 返回 422，指出材料字段必须是列表。
  4. Python Word 渲染本身正常：直接向同一个报告引擎发送合法材料包，成功生成可打开的 DOCX，包含来源 URL 和维度结论。该项无 LLM Key，只证明文件渲染，不能证明 AI 报告内容。

代码定位（只读审查）：HTML 下载读取分析当前 report_content，见 platform/internal/api/v1/reports.go:94；下载服务要求请求格式等于报告记录格式，见 platform/internal/business/report/service.go:126；Word 请求仅装配标题、分析 ID、话题、情感和格式，见 platform/internal/api/v1/reports.go:153；主报告管线则会传递文档、维度、日期和场景，见 platform/internal/app/pipeline.go:223；管线创建的报告记录是 HTML，见 platform/internal/business/analysis/pipeline.go:563。报告中心对所有已完成记录展示全部格式操作，见 web/src/pages/ReportHistoryPage.tsx:92 和 web/src/lib/constants.ts:122。

其余通过项包括：空报告列表、未知 ID 404、HTML 内容字节与保存内容一致、未认证 401、跨租户读取/下载 404、Lite Word 403、读写导出不消费额度、导出不创建供应商授权。

后续建议

  1. 先确定报告中心的产品契约：每份报告是否为不可变快照；HTML 报告是否应动态导出其他格式；下载选项应按记录格式展示还是代表转换操作。
  2. 让 Word 请求完整传递源材料、背景材料、研判维度、时间范围、场景/模板和来源证据，并对 FastAPI 的 422 返回可诊断错误。
  3. 检索失败时保存受控的上游 HTTP 状态/类别和脱敏 request id，便于区分认证、限流、网络和供应商故障；随后再重跑一次真实任务完成来源、报告和计费对账。
  4. 上述缺陷修复后重跑同一报告专项，要求 HTML 历史字节稳定、格式操作与 UI 契约一致、DOCX ZIP/XML 可打开且来源信息完整，再重新检查发布门禁。
