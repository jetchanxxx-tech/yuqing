系统架构

浏览器 ──HTTPS(443)──▶ nginx ──┬── /            → /opt/yuqing/web/dist   React 静态文件
                                └── /api/*       → 127.0.0.1:8080          Go API

Go 平台层（systemd）:
  yuqing-server   无状态 HTTP API
  yuqing-worker   队列消费 + 定时任务

Python 引擎层（systemd，仅内网监听）:
  8000 query     Bocha 搜索 + Scrapling 抓取
  8001 media     多模态理解
  8002 insight   情感分析 + 话题聚类
  8003 report    报告生成
  8004 forum     多 Agent 辩论

数据层:
  PostgreSQL 16   127.0.0.1:5432   平台库 + 租户库
  Redis 7         127.0.0.1:6379   缓存/计数/限流

服务管理

查看状态

# 一次看全部
systemctl is-active yuqing-server yuqing-worker yuqing-query yuqing-media \
  yuqing-insight yuqing-report yuqing-forum nginx

# 详细状态
systemctl status yuqing-server

重启

# 单个服务
systemctl restart yuqing-server

# 全部引擎
systemctl restart yuqing-query yuqing-media yuqing-insight yuqing-report yuqing-forum

# 全部服务
systemctl restart yuqing-server yuqing-worker yuqing-query yuqing-media \
  yuqing-insight yuqing-report yuqing-forum

启动 / 停止 / 开机自启

systemctl stop yuqing-worker          # worker 无状态，可随时停
systemctl start yuqing-worker
systemctl enable yuqing-server        # 开机自启（部署时已配置）
重启影响：Go 平台使用内存存储，重启会清空所有数据（账号、分析、报告）。引擎无状态，重启无影响。

日志排查

实时日志

journalctl -u yuqing-server -f        # Go API

tail -f /var/log/nginx/access.log     # nginx 访问日志

日志格式

Go 服务输出 slog JSON，含 request_id、actor_id、tenant_id，可用于链路追踪：

{"time":"2026-09-13T02:50:12+08:00","level":"INFO","msg":"request",
 "method":"POST","path":"/api/v1/auth/register","status":201,
 "latency":399973132,"tenant_id":"01M2B1J7YB..."}

常用过滤

# 只看错误
journalctl -u yuqing-server -p err --no-pager | tail -20

# 最近 100 行
journalctl -u yuqing-server -n 100 --no-pager

# 按时间范围
journalctl -u yuqing-server --since "1 hour ago"

curl -X PUT https://yuqing.pangu-cloud.com/api/v1/admin/settings \
  -H "Authorization: Bearer <platform_admin token>" \

版本更新

注意：服务器访问 GitHub 存在间歇性中断。若 git pull 失败，改用本地打包 + SCP 上传。
# 1. 拉取代码
cd /opt/pangu-source && git fetch --depth 1 origin main && git reset --hard origin/main

# 2. 重新部署（幂等，已完成的步骤自动跳过）
export YUGING_DOMAIN=yuqing.pangu-cloud.com
export BOCHA_API_KEY=<key>
export YUGING_BOOTSTRAP_ADMIN_EMAIL=admin@pangu.com
bash scripts/deploy.sh

只更新 Go 二进制

cd /opt/pangu-source/platform
export PATH=/usr/local/go/bin:$PATH
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath -ldflags="-s -w" \
  -o /opt/yuqing/bin/yuqing-server ./cmd/server
systemctl restart yuqing-server

只更新前端

cd /opt/pangu-source/web && npm run build && cp -r dist /opt/yuqing/web/

只更新 Python 引擎

# 改完代码后语法自检
/opt/yuqing/engines/venv/bin/python -m py_compile /opt/pangu-source/engines/*/main.py
systemctl restart yuqing-query    # 换对应引擎名
引擎代码修改注意：Python 代码中的中文文案必须使用全角引号「」。混入 ASCII 双引号会提前终止字符串字面量导致 SyntaxError，服务反复重启（曾因此故障）。

证书管理

当前证书

项目值
域名yuqing.pangu-cloud.com
颁发者Let's Encrypt
工具acme.sh（~/.acme.sh/acme.sh）
有效期90 天
自动续期每日 cron 检查，到期前 30 天自动续期（≈ 每 30 天一次）
续期后动作systemctl reload nginx（已写入 reloadcmd）

查看续期状态

grep -E 'Le_NextRenewTime|Le_ReloadCmd' \
  ~/.acme.sh/yuqing.pangu-cloud.com_ecc/yuqing.pangu-cloud.com.conf

crontab -l | grep acme          # 确认 cron 存在

手动续期

~/.acme.sh/acme.sh --renew -d yuqing.pangu-cloud.com --ecc --force

手工签发（首次或重建）

~/.acme.sh/acme.sh --issue -d yuqing.pangu-cloud.com \
  --webroot /opt/yuqing/web/dist --server letsencrypt

~/.acme.sh/acme.sh --install-cert -d yuqing.pangu-cloud.com --ecc \
  --key-file       /etc/nginx/ssl/yuqing.pangu-cloud.com/key.pem \
  --fullchain-file /etc/nginx/ssl/yuqing.pangu-cloud.com/fullchain.pem \
  --reloadcmd      "systemctl reload nginx"
关键约束：nginx 的 HTTP 块必须保留 /.well-known/acme-challenge/ 的 webroot 路径 —— 该路径不能重定向到 HTTPS，否则续期时 ACME 挑战会被 301 打断，导致续期失败。

备份恢复

当前状态：应用使用内存存储，重启即丢失数据。PostgreSQL 已安装但未接入应用。以下为数据库层面的备份命令，接入后即可生效。
# 备份平台库
sudo -u postgres pg_dump yuqing_platform > /root/backup_$(date +%F).sql

# 备份配置与证书
tar czf /root/pangu-config_$(date +%F).tar.gz \
  /opt/yuqing/config /etc/nginx/ssl /etc/nginx/conf.d/yuqing.conf

# 恢复
sudo -u postgres psql yuqing_platform < /root/backup_2026-09-13.sql

建议的定时备份

sudo crontab -e
# 每日 03:17 备份
17 3 * * * /usr/bin/pg_dump -U postgres yuqing_platform > /root/backup_$(date +\%F).sql

故障排查手册

以下均为实际发生过的故障及定位方法。

服务起不来 / 健康检查失败 
systemctl status yuqing-server
journalctl -u yuqing-server -n 50 --no-pager
ls -la /opt/yuqing/bin/          # 确认二进制存在且命名正确

历史原因：二进制被构建成 cli/server/worker（Go 用包目录名），而 systemd 找的是 yuqing-server。检查文件名是否带 yuqing- 前缀。

外部访问返回 nginx 欢迎页 
grep -r default_server /etc/nginx/sites-enabled/ 2>/dev/null
nginx -T | grep -B2 'server_name'

历史原因：Ubuntu 自带的 sites-enabled/default 占着 default_server，请求全落到 /var/www/html。需把它移出 sites-enabled 目录（仅改名无效，include 会加载目录下所有文件）。

nginx 配置校验失败 
nginx -t
journalctl -u nginx -n 20 --no-pager

常见原因：① ssl_certificate 指向不存在的证书文件；② 使用了 nginx 1.24 不支持的指令（如独立的 http2 on;，需 1.25.1+）。

某个 Python 引擎反复重启 
journalctl -u yuqing-query -n 40 --no-pager | tail -20
/opt/yuqing/engines/venv/bin/python -m py_compile /opt/pangu-source/engines/query_engine/main.py

历史原因：中文文案里混入 ASCII 双引号 → SyntaxError。堆栈较长时先看最后几行的错误类型。

Go 依赖下载超时 
export PATH=/usr/local/go/bin:$PATH
go env GOPROXY      # 应为 https://goproxy.cn,direct
go env -w GOPROXY=https://goproxy.cn,direct

历史原因：proxy.golang.org 在境内不可达。

npm 安装缓慢或失败 
npm config get registry     # 应为 https://registry.npmmirror.com
npm config set registry https://registry.npmmirror.com
管理后台返回 403 
systemctl cat yuqing-server | grep BOOTSTRAP
curl -s https://yuqing.pangu-cloud.com/api/v1/auth/me -H "Authorization: Bearer $TOKEN"

原因：当前账号缺少 platform_admin 角色。/admin/* 要求该角色。引导邮箱由 YUGING_BOOTSTRAP_ADMIN_EMAIL 配置，用该邮箱注册的账号即具备权限。

Windows 客户端 HTTPS 报证书吊销错误 
# Windows curl 报错
CRYPT_E_REVOCATION_OFFLINE (0x80092013)

这不是服务器问题。Windows Schannel 无法连接证书吊销服务器所致。验证时加 --ssl-no-revoke；浏览器不受影响。

git pull 失败（GnuTLS recv error）

GitHub 从境内访问存在间歇性中断。绕过方式：本地打包 + SCP 上传。

# 本地
tar czf /tmp/src.tar.gz --exclude='.git' --exclude='node_modules' --exclude='dist' .
scp /tmp/src.tar.gz root@<host>:/tmp/
# 服务器
tar xzf /tmp/src.tar.gz -C /opt/pangu-source
