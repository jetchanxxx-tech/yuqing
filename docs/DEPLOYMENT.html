部署指南

Ubuntu 24.04 · 无 Docker · 已装 Nginx · 单机部署

部署拓扑

# 单台服务器，全部进程由 systemd 守护
浏览器 ──HTTPS──▶ nginx (80/443)      ← 已存在，仅添加站点配置
                   ├── /          → /opt/yuging/web/dist   前端静态文件
                   └── /api/*     → 127.0.0.1:8080        Go API

systemd 服务:
  yuging-server   Go API 进程（无状态 HTTP）
  yuging-worker   Go 后台进程（队列消费 + 定时任务）

数据组件:
  PostgreSQL 16   平台库 yuging_platform + 每租户一库
  Redis 7         缓存/计数/限流
  /opt/yuging/    二进制 + 前端 + 配置 + 数据 + 日志

一键部署

获取代码

git clone https://github.com/jetchanxxx-tech/yuqing.git /tmp/yuqing
cd /tmp/yuqing

执行部署（幂等，可重复运行）

sudo YUGING_DOMAIN=yuqing.example.com bash scripts/deploy.sh

首次部署约 3–8 分钟（下载依赖）。输出中 [SKIP] 表示检测到已有组件自动跳过。

填入 JWT 密钥（首次部署后必须）

sudo nano /opt/yuging/config/config.yaml   # 编辑 jwtSecret: 随机长字符串
sudo systemctl restart yuging-server yuging-worker

访问验证

curl https://yuqing.example.com/api/v1/health
→ {"status":"ok"}
⚠ 首次部署后必须做：1) 改数据库密码（默认 yuging）；2) 填 jwtSecret；3) 数据库迁移 CLI 当前为占位，需手工执行 migrations/platform/0001_init.sql（见部署日志提示）。

手动分步部署

1. 系统依赖

# nginx 已存在 → 跳过
sudo apt-get install -y postgresql postgresql-contrib redis-server \
    python3-venv python3-pip certbot python3-certbot-nginx

# Go ≥1.25（apt 自带 1.22 不够）
curl -fsSL https://go.dev/dl/go1.25.5.linux-amd64.tar.gz -o /tmp/go.tgz
sudo rm -rf /usr/local/go && sudo tar -C /usr/local -xzf /tmp/go.tgz

# Node ≥20.19（Vite 8 要求，apt 自带 18 不够）
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo bash -
sudo apt-get install -y nodejs

2. 数据库初始化

sudo -u postgres createdb yuging_platform
sudo -u postgres psql -c "CREATE USER yuging WITH PASSWORD 'yuging' CREATEDB;"
sudo -u postgres psql -c "GRANT ALL PRIVILEGES ON DATABASE yuging_platform TO yuging;"

# 迁移（CLI 占位期间手工执行 SQL）
sudo -u postgres psql -d yuging_platform \
    -f platform/migrations/platform/0001_init.sql
数据库用户需要 CREATEDB 权限 — 租户注册时自动创建独立数据库（database-per-tenant）。

3. 构建

# Go 交叉编译（部署机即构建机，无需 Go 环境的目标机）
cd platform
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath -ldflags="-s -w" \
    -o /opt/yuging/bin/ ./cmd/...

# 前端
cd ../web && npm ci --no-audit --no-fund && npm run build
cp -r dist /opt/yuging/web/

4. 配置

sudo cp platform/config.example.yaml /opt/yuging/config/config.yaml
sudo chown yuging:yuging /opt/yuging/config/config.yaml
sudo chmod 600 /opt/yuging/config/config.yaml
sudo nano /opt/yuging/config/config.yaml

5. systemd 服务

sudo cp scripts/systemd/*.service /etc/systemd/system/
sudo useradd -r -m -d /opt/yuging -s /usr/sbin/nologin yuging
sudo systemctl daemon-reload
sudo systemctl enable --now yuging-server yuging-worker

6. nginx 站点（与已有 nginx 共存）

sudo sed "s/your-domain.com/你的域名/g" scripts/nginx.conf \
    > /etc/nginx/conf.d/yuging.conf
sudo nginx -t && sudo systemctl reload nginx
sudo certbot --nginx -d 你的域名   # SSL 证书

配置说明

配置项说明必改
auth.jwtSecretJWT 签名密钥，至少 32 字符随机串✅ 是
db.primary平台库连接串（含 yuging 用户密码）✅ 是
server.addrAPI 监听地址（nginx 反代目标，保持 :8080）否
queue.drivermemory / redis / rabbitmq / nats单机用 memory
llm.models[].apiKey大模型 API key（联调阶段填，当前 FakeProvider 不需要）暂不需要
db.tenant.maxPools租户连接池上限 50，超出 LRU 驱逐否
storage.driverlocal 文件存储 / s3单机用 local
search.driverpg tsvector / elasticsearch单机用 pg

环境变量覆盖（如 APP_AUTH_JWT_SECRET）优先级高于 yaml。

systemd 管理

# 状态与日志
systemctl status yuging-server
journalctl -u yuging-server -f          # 实时日志（slog JSON）

# 启停
systemctl stop yuging-worker            # 先停 worker（无状态，随时可停）
systemctl restart yuging-server

# 开机自启
systemctl enable yuging-server yuging-worker

配置变更后重启：systemctl restart yuging-server yuging-worker；Go 二进制更新后同样重启即可。

与已有 Nginx 共存

脚本不安装、不重装已有 nginx，只新增一个站点文件 /etc/nginx/conf.d/yuging.conf：

server {
    listen 443 ssl http2;    # 80 端口 http 由脚本可选配置跳转
    root /opt/yuging/web/dist;
    location / { try_files $uri /index.html; }          SPA 回退
    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_buffering off;                             SSE 支持
    }
}
如果已有站点配置也监听 443 且同域名，请检查 server_name 冲突。yuging.conf 只占一个 server block，不影响其他站点。

常见问题

Q: 部署后注册的用户重启就没了？

当前 MVP 用内存 store（无外部依赖快速跑通）。生产数据持久化需接 PostgreSQL store（架构已预留 store 接口，替换实现即可），这是 REVIEW_REPORT 中的遗留项。

Q: 为什么分析结果没有真实数据？

爬虫与 LLM 调用当前为 Fake 实现（token 绕过策略）。待提供真实 API key 后替换 HTTP transport，业务代码零改动。

Q: 部署脚本重复运行安全吗？

安全。所有组件安装前检测（已装打印 SKIP），配置文件/数据库/nginx 站点已存在绝不覆盖。可放心重跑补齐缺失项。

Q: nginx 已被其他项目占用怎么办？

无冲突。脚本只新增 conf.d/yuging.conf，通过 server_name 区分虚拟主机。若 443 端口被占且域名不同，nginx 自动按 SNI 分流。

Q: 数据库迁移为什么报占位提示？

yuging-cli migrate 当前为占位实现，未接 goose。按部署日志提示手工执行 migrations/platform/0001_init.sql。goose 接线在遗留清单中。

Q: 多机扩展怎么配？

架构为配置驱动扩展：queue.driver 切 redis/rabbitmq、db.replicas + readWriteSplit 读写分离、storage.driver 切 s3、nginx upstream 轮询多 api 实例 — 全部改配置零代码。
