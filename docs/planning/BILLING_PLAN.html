四、技术实现（开发方案）

4.1 数据库（goose 0006/0007，复用 0001 已有 subscriptions 表 ALTER 扩列）

-- 0006_billing_core.sql（核心段）
ALTER TABLE subscriptions ADD COLUMN IF NOT EXISTS billing_cycle TEXT NOT NULL DEFAULT 'monthly',
  ADD COLUMN IF NOT EXISTS auto_renew BOOLEAN NOT NULL DEFAULT false,
  ADD COLUMN IF NOT EXISTS canceled_at TIMESTAMPTZ,
  ADD COLUMN IF NOT EXISTS updated_at TIMESTAMPTZ NOT NULL DEFAULT now();

CREATE TABLE report_credits (            -- 报告配额池：每次发放一行，先到期先扣
  id TEXT PRIMARY KEY, tenant_id TEXT NOT NULL,
  credit_type TEXT NOT NULL CHECK (credit_type IN ('quick','deep')),
  total INTEGER NOT NULL CHECK (total > 0),
  remaining INTEGER NOT NULL CHECK (remaining >= 0 AND remaining <= total),
  source TEXT NOT NULL CHECK (source IN ('subscription','addon','trial','manual')),
  ref_id TEXT NOT NULL DEFAULT '', expires_at TIMESTAMPTZ NOT NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now());
CREATE INDEX idx_report_credits_consume
  ON report_credits(tenant_id, credit_type, expires_at) WHERE remaining > 0;

CREATE TABLE credit_transactions (       -- append-only 流水，幂等键防重复
  id BIGSERIAL PRIMARY KEY, tenant_id TEXT NOT NULL, credit_id TEXT NOT NULL,
  analysis_id TEXT NOT NULL DEFAULT '',
  kind TEXT NOT NULL CHECK (kind IN ('consume','grant','refund','expire','adjust')),
  amount INTEGER NOT NULL, balance_after INTEGER NOT NULL,
  operator TEXT NOT NULL DEFAULT 'system', idempotency_key TEXT NOT NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(), UNIQUE (idempotency_key));
ALTER TABLE analyses ADD COLUMN IF NOT EXISTS credit_type TEXT NOT NULL DEFAULT '';

4.2 计费引擎（internal/business/credit/）

TryConsume(ctx, tenantID, typ, n, analysisID) error      // 幂等键 = analysisID+":consume"
Grant(ctx, tenantID, typ, n, source, refID, expiresAt) error
RefundByAnalysis(ctx, tenantID, analysisID) error        // 任务失败/取消回补，幂等
Balance(ctx, tenantID) (Balance, error)
Entitlement(ctx, tenantID) (PlanEntitlement, error)      // 深度研判/PDF/API 可用性
ExpireDue(ctx, now) (int64, error)                       // 定时过期

原子性与防超卖：Create 生成 ID 后、落库+发布前 TryConsume；发布失败立即 RefundByAnalysis 回补；管线 markFailed/Cancel 挂回补。单事务 SELECT FOR UPDATE（expires_at ASC 分摊多行）+ 条件 UPDATE 双保险；行锁粒度 = 租户×类型。超量语义：Lite 余额 0 → QUOTA_EXCEEDED（停服）；Pro/Ent 余额 0 → QUOTA_EXCEEDED_ADDON（引导加购）。

4.5 通知与实施顺序

通知挂钩：TryConsume 扣后 ≤20% → quota.warning、=0 → quota.exhausted；ExpireDue 扫描订阅到期前 7/3 天；MarkPaid → order.paid。通道抽象 Notifier（站内落库先行，邮件 nil 降级先例）。实施顺序：P0（0006 + credit.Service TDD + 方案 B 套餐目录 + Create 扣减 + 维度裁剪 + 试用 Grant）→ P1（0007 + ManualProvider + orders + 到期定时 + 通知）→ P2（Alipay/Wechat provider、优先队列、PDF、SMTP）。

4.6 风险对策

并发超卖（条件 UPDATE + FOR UPDATE + 幂等键三重，集成测试并发 50 断言不为负）｜到期宽限 3 天 past_due 只读｜试用滥用（trial 租户级幂等一次，P2 手机风控）｜退款反向流水、已消耗不自动回收｜Lite 停服只拦创建/下载，GET 永不拦。
