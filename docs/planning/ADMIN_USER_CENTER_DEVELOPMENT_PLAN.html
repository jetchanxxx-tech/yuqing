03 / 后台与用户中心

页面与操作定义

管理员后台：两个管理入口，复用现有配置

入口列表／详情操作与交互
用户账号管理列表：用户 ID、昵称、邮箱、脱敏手机号、账号状态、邮箱／手机验证、平台角色、关联租户数、创建／最后成功登录时间。搜索邮箱／昵称／ID，按状态／角色／验证筛选，服务端分页。详情分「平台角色」与「团队成员角色」，每个成员行明确租户／role／row_version；另有验证、最后改密与审计，无设备记录。P0：查看、禁用／启用、平台管理员授撤、现有成员 tenant_admin／analyst／viewer 变更；两类角色独立确认。P1：新建账号及初始团队、编辑昵称、发重置链接。删除进入注销预检；邮箱／手机由本人验证，管理员不能直接标已验证。
租户／套餐管理列表：租户 ID／名称、状态、有效套餐、成员人数、剩余额度、创建时间。按状态／套餐筛选；详情显示成员及其基本角色操作、报告／分析数量、额度流水、真实订单、挂起记录。套餐表列现有目录与权益来源，无有效周期数据则明确显示。P0：挂起／恢复、详情、现有成员基本角色变更（与用户详情共用用例）。P1：带原因额度调整。P2：确认规则后人工套餐变更。账号禁用不关闭团队；挂起不删账号、不自动退款；不新增成员／邀请。
现有配置数据源、通知服务、支付渠道保留原入口；通知明确展示「供应商已选择／配置完整性待核对／受控验收结果」，敏感值只返回掩码及 configured 标志。保存空输入表示「不修改」；清除秘密要独立确认。错误、超时和供应商拒绝不可显示发送／支付成功。用途模板分别设置，不能拿绑定模板宣称手机登录已可用。

共同状态：初次加载、加载失败＋重试、无数据、筛选无结果、无权限必须区分。操作提交时按行锁定按钮，返回成功后重新取详情与列表；业务冲突用 409 显示原因，网络超时先重新读取目标状态、按幂等键安全重试，request_id 用于支持排查。发送类不能盲目重发；危险动作展示目标／影响范围，要求原因与确认，不能仅靠 UI 乐观成功。

用户中心：保留四个 Tab，明确自助流程

  • 账户概览：从新鲜 /auth/me 与 profile 读取身份；套餐／额度来自现有权益服务。显示账户与团队两个状态，不把运营挂起混作用户禁用。
  • 个人资料：昵称与时区复用；加入头像上传／删除。时区须验证为 IANA 标识，保存后影响全站时间展示，含管理员表格、订单、分析、报告列表与安全页。
  • 账户安全：改密保留；换邮箱须验证当前密码和新邮箱，确认前旧邮箱仍是登录标识；成功后撤销旧 token 并通知旧邮箱。注销预检、申请与状态放在本 Tab。
  • 手机绑定：保留验证码绑定及密码解绑，补换绑确认。绑定手机可作登录／找回入口的能力在 P1 真正上线后才展示；支付敏感确认另列 P2 依赖。
  • 登录／找回：既有邮箱登录继续可用；P1 增加「已绑定手机号＋短信码」登录与邮箱／已验证手机找回。未知手机号不会隐式注册或创建租户。

时区只改变明确 UTC 时刻的展示与日期筛选边界，数据库仍用 TIMESTAMPTZ／UTC。仅有日期或缺少来源时区的原文时间保留原精度并明确标注，不能擅自当作 UTC 时刻换日。账单周期、credit 策略与既有聚合口径不因用户改时区而重算；导出若暂未接入用户时区，必须标注其固定时区。

04 / 技术决策

保持单体，补齐真实权限边界

React 页面／DTO表单、状态、分页、错误展示
Gin handler／鉴权当前账号与角色、路由权限
应用用例／领域规则状态跃迁、最后管理员、一次性凭据
端口与适配器PG 事务、头像存储、Resend／SMS
方案收益代价／选择
A：单体＋PG 即时鉴权＋账号 token_version改密／禁用／角色撤销直接使账号旧 token 失效；无需设备会话表。11 个账号规模可直接查询，持久化可验证。每次请求增加 PG 查询；PG 故障时鉴权失败。推荐本轮采用。授权状态不做存在过期窗口的缓存。
B：登录会话服务＋Redis／设备 token 记录能做逐设备撤销、集中会话统计与更细粒度限流。增加存储与多实例一致性、设备模型和迁移负担；超出已确认范围。暂缓，未来可在现有鉴权端口后演进。

拟定 ADR-A：当前数据库状态决定授权

状态：Proposed JWT 只携带身份 ID、明确 token_kind=access|refresh、token_version 和有效期。鉴权从数据库读取账号状态／版本、平台角色、当前成员关系和租户状态，重建 principal；不信任旧 token 的角色、套餐、挂起标志。刷新必须验证 refresh 类型，并重新解析同一身份的当前权限。

  • 密码变更／重置、禁用、角色变更、邮箱或手机身份变更、注销申请：在同一事务更新数据与递增 token_version。事务提交后的下一次旧 access／refresh 请求返回 401；账号禁用后任何登录方式也拒绝。
  • 发布后拒绝缺少版本／类型的旧格式 JWT，并安排一次统一重新登录。保留当前 token TTL；不做设备列表、refresh 逐设备轮换或新会话页面。
  • 路由分组：普通账号路径要求 active 用户；管理员路径额外校验平台角色；租户业务路径必须有当前成员且租户 active。挂起租户的 active 用户可进入受限用户中心，平台管理员仍有恢复权限。P2 的 closure_pending 可用原密码重新登录取得新版本 token，但最新 DB 状态仅放行注销状态、退出及政策允许的撤回路径，其余 403；不新建会话体系。此为拟定路由策略，确认文案须同步。
  • 租户挂起提交后，旧 JWT 与 API Key 的新业务请求均 403；provisioning／closed 同样阻断。已有请求和供应商外部调用无法撤回：关键写入／队列领取及任务阶段边界复核状态，停止新增工作；任务取消和回补复用既有语义，不引入新的计费政策。
  • 用户中心仅接受真实用户 JWT，API Key 不能进入换密／解绑／换邮箱／注销路由。/auth/me 与刷新后 UI 重新取角色、时区和状态。

拟定 ADR-B：平台管理员落库，成员角色保持团队语义

状态：Proposed 新建平台角色关联表；platform_admin 不再由邮箱永久动态授予。已有引导账号通过预构建 CLI 按明确 user_id 一次性入库；启动不再按环境邮箱追加。换邮箱后平台角色跟随 user_id，撤销后不能靠原邮箱重新获得权限。

平台角色授撤、禁用、注销共享 PG 事务级管理员锁：操作后至少一名 active 平台管理员，角色／状态／版本／审计同时提交；并发互撤只能一个成功。成员角色独立保存在 tenant_members.role，只允许修改显式租户中已存在成员的 tenant_admin／analyst／viewer，不能写入 platform_admin／api_service。每个租户的角色变更持有租户事务锁，检查成员版本且至少保留一个 tenant_admin；降级最后一名返回 409，提交时递增成员 row_version 与目标账号 token_version，下一请求按当前成员角色授权。审计记录目标 tenant_id／user_id、前后角色、原因与操作者；不新增成员、邀请或协作功能。

拟定 ADR-C：PG 是生产事实源，秘密写入和操作留痕

状态：Proposed 复用 auth、tenant、credit／payment、settings 模块；增加小型 platform/accountadmin 应用服务组合账号管理端口。领域规则不依赖 Gin／pgx，PG Store 实现事务。业务模块不得直接 import 平台模块，新队列／任务状态检查通过组合根注入函数。

管理员查询聚合账号＋成员＋租户的读 DTO，服务端参数白名单，避免 N+1 与跨租户数据混用。复用现有 audit_logs 表记录 actor、目标、前后状态、原因、request_id 与时间；当前请求 logger 不能替代持久操作审计。密码、JWT、验证码与完整供应商密钥不进入 DTO 或审计。

A1 · P0U1 先取得 access＋refresh；本人改密／管理员禁用／撤角色后分别重放两类 token。refresh 当 access 使用、access 当 refresh 使用。提交后旧 token 全部 401，类型混用拒绝；disabled 的密码／手机登录及 reset 不激活。启用后原 token 仍不可用。PG 上执行，同秒改密不受 iat 精度影响。
A2 · P0以 active JWT／API Key 访问租户后挂起；重放查询／创建／下载／订单接口并尝试队列领取。恢复再登录。挂起提交后的新租户请求 403，恢复状态由 DB 生效；provisioning／closed 也阻断。后台恢复入口在管理员个人租户挂起时仍可用，用户中心受限边界与契约一致。
A3 · P0平台管理员并发互撤／禁用最后一名；同租户两名 tenant_admin 并发降级，重放成员旧版本／旧 JWT；跨租户或不存在成员、写 platform_admin／api_service；降为 viewer 后验证写接口，重启查角色／审计。平台 active 管理员与各租户 tenant_admin 均至少留一名，最后一名／版本冲突 409；无成员 404，非法角色 400，不增成员或改其他团队。成功旧 token 401、新登录按新角色授权，审计包含 tenant 与前后角色且 PG 重启保留；bootstrap 不重授，tenant_admin／viewer／API Key 调 admin 均 403。
A4 · P0注册／账号或租户操作后重启应用；开户第二／第三写入注入失败；多人租户、空列表、同创建时间分页；方案源有差异。状态／角色／审计／资料仍在，开户失败不遗留孤儿行；created_at 为真实值、user_count 等于成员数；分页稳定。effective plan 与现有报告权限一致，没有同步伪造购买。
A5 · P1同凭据并发两次提交、重发旧码、五次错误、过期、跨目的、不同用户绑同目标；发送失败；服务重启后继续尝试。至多一次更新／消费，旧码不能重放，尝试次数／发送窗口持续有效，DB 不留明文 token／code；供应商失败不会绑手机／换邮箱或显示已送达。
A6 · P1指定 Resend 邮箱与阿里云手机真实收件，点验证／恢复／换邮箱链接并提交绑定／登录码；已知／未知目标及单次供应商失败请求。脱敏 provider ID＋受理／收件／页面／DB 结果链完整；公开请求状态／文案一致，202 只代表受理，错误留后台记录。模板匹配，无密码或码入日志；未实测不签通过。
A7 · P1已验证绑定手机登录、手机／邮箱找回；新邮箱确认前用旧邮箱登录，新邮箱与他人并发抢占；头像畸形／过大／跨用户删除。未知手机号无 users／tenants 新行；同一 principal／安全规则；未确认不换邮箱，唯一冲突回滚，不丢旧凭据；文件校验／归属生效且删除不影响他人。
A8 · P1切 Asia/Shanghai → America/New_York，覆盖夏令时边界与 UTC 跨日；重载后查分析／报告／订单／安全时间；无效时区。同一 UTC 时间展示跟随个人时区并标识，浏览器时区不同仍一致；invalid IANA 拒绝。后台日期筛选转换明确；数据库与计费周期不重算。
A9 · P1账号创建中断／激活链接重放；并发负额度调整；同 idempotency_key 再次请求／不同参数；密码重置发送失败。开户无孤儿、试用至多一次；用户自己设密，明文不返回管理员；余额≥0、流水原因完整、单次审计，无 paid 假记录；失败在 UI 明确可重试。
A10 · P2单人／多人团队、未结订单／退款／任务的注销预检；申请后以原密码重登取状态并尝试普通业务路径；回收中断再执行。pending 状态可读且所有普通业务路径 403；blocker 生效，不误删他人报告／财务流水；期限按批准政策执行，回收幂等／可观察，不报告未清理数据为已删除。

10 / 注销与回收

删除账号前，先定义团队与资产归属

提案采用「预检 → 申请 → closure_pending／撤 token → 经批准的等待期 → 执行清理 → closed／脱敏」；财务、合同或安全调查保留事项由产品／财务确认。预检与确认瞬间都检查当前数据，不能沿用过期影响快照。

对象／情形拟定安全默认处置与回收
全局用户禁用仅阻止此账号；注销申请撤销旧 JWT／验证凭据。pending 身份只能读取注销状态／按批准策略撤销申请，不访问团队业务。完成时清除或匿名化邮箱／手机号／昵称／头像，保留无身份信息的 user_id tombstone 供审计引用。邮箱／手机能否重用由政策确认，不能在处理中释放唯一约束。
最后平台管理员拒绝注销／禁用／降权，不允许流程绕过 K2 的共享管理员锁。先由另一个经验证的 active 管理员承接；不是设备管理或账号注销的特例后门。
多人团队不因某个成员注销删除租户／其他成员数据。若申请人是唯一 tenant_admin，阻止执行并进入运营责任转交流程。可用 K2 的现有成员角色变更先提升承接者再降级申请人，不新增邀请／协作；或单独批准团队关闭。成员退出／账号匿名化与团队业务资产分开处理。
单人团队预检显示团队资产、credit、订单与任务影响；申请人确认团队关闭意图，经政策确认后才执行。停 API Key／新任务，取消或结清执行中任务；租户先 closed／归档，未来定时清理其报告、原始文档与相关文件。不直接 CASCADE 删除整条租户。
订单／额度／财务pending／paid 尚未 granted／refund_needed／未完成退款／争议账单阻止自动完成，走补偿与财务处理。orders、credit_transactions、invoice 与必要审计按确认的财务留存期保留，关联账号脱敏；注销不自动退款、不将订单改 paid、不销毁流水。剩余额度处理需业务确认。
报告／分析／文件／备份团队资产仍归租户，created_by 可引用 tombstone。实际保存期读取套餐／批准政策，不能沿用页面旧 30／90／365 文案。回收作业逐批删除 DB 业务行与文件，失败重试、统计剩余数，记录完成时间；备份按轮换策略到期，并确保从备份恢复后重新应用 tombstone／清理记录。

「撤销注销申请」若纳入政策，必须验证密码／批准的恢复渠道且重新发 token；「全部已删除」只在在线数据清理完成后显示。若财务记录／备份仍需保留，应准确说明范围与到期条件。

11 / 发布与回滚

从 dev 到 prod 的分阶段发布

  1. 开工基线：恢复 Git 工作区元数据，固定 dev 源码 SHA，核对最新迁移与运行配置。先在 GitHub PostgreSQL 服务复刻历史 schema 并升级；测试数据不得来自生产凭据或完整真实用户。
  2. 审查与 CI：每包在 dev 分支／PR 跑两工作流。失败新提交修复并重跑，不能降级为本地 build。涉及角色／验证／注销的 PG 测试必须实际执行。
  3. 生产准备：运维保存当前源码 SHA、二进制／前端产物、受保护配置、迁移版本；做 PostgreSQL 一致性备份，并在隔离恢复环境验证可恢复。备份与敏感配置不进入公开仓库。
  4. 合并和产物：dev → prod PR 完成评审与 required checks，合并后为 prod 准确目标 SHA 重新跑成功构建。PR merge SHA、其他分支／旧提交或未完成 run 的包均不能代替。必需 Go／frontend／PG／package 检查全绿。
  5. 校验安装：选择成功 prod run 的 yuqing-release-<SHA>，下载归档＋外部 .sha256；校验归档、BUILD_COMMIT 与解包后的 SHA256SUMS。服务器只校验、解包、运行新预构建 yuqing-cli migrate platform、配置、启停与健康检查；缺二进制／dist 直接失败。
  6. 迁移和切换：先增量扩表，再入库现有管理员；完成至少一名 active 管理员核对后发布安全修复包并统一重登。安全修复全局生效；账号创建／找回／注销等新功能按独立配置默认关闭、测试租户先开。配置开关不得关闭禁用／版本／挂起校验。
  7. 前端与检查：先安装 hash 命名 assets，再原子替换 index.html；保留旧 assets 与 rollback 包。验收健康、管理员登录／恢复、普通角色拒绝、改密旧 token 401、挂起 403、profile 与 PG 审计读取；不执行未经授权的短信／邮件发送或真实支付。
  8. 扩大开放：观察新旧 token 拒绝、role／状态冲突、PG 错误、恢复成功率、供应商受理与失败、发送量／费用、注销回收失败。观察时间由实际流量与验收负责人确定，不编造无流量的成功指标。
回滚限制：优先关闭新功能入口，安全校验继续生效。备份增量表不执行 destructive Down；头像／验证／注销数据需保留。最早允许回退的应用包必须已经具备数据库状态校验、持久角色与 token_version，否则回滚会让已撤销凭据重新有效。无法保持安全能力时，停止敏感入口、修复后由 GitHub 构建新包，不能重开旧不安全鉴权。

发布要记录 SHA／run ID／校验结果／迁移版本／备份与回滚包位置／操作者／健康验收。上面是实施阶段 runbook 提案；本次仅写计划，没有推送、发布、迁移或连接生产。

12 / 决策与交接

继续开发所需的业务决策

决策默认假设／影响阻塞的任务
D1 试用／计费／套餐已确认：只有初始 admin@pangu.com 对应且经核对的固定 user_id 豁免次数和消费限制；其他账号按所选套餐执行计费。删除全局公测 bypass 的前提是实现 PG 原子计费及精确本轮退款，保留现有套餐价格和可核对的存量额度。邮箱验证不增加额度；人工权益变更与付款分开，额度调整单独审计，不制造 paid 或退款记录。不阻塞 P0／P1；阻塞新政策与 K11 的人工权益写入。现有 POST /admin/plans 返回 501，不能启用假成功套餐编辑。
D2 注销等待期／身份回用已确认：七天内可撤回；未结订单阻止完成；单人团队必须明确确认一起关闭；多人团队保留其他成员资产，唯一团队管理员须先交接。完成匿名化后才释放可复用邮箱／手机，pending 期间仍绑定原账号。K10 执行按钮／作业。
D3 财务与数据留存已确认：财务流水保留并脱敏，业务文件按已有套餐保留期清理，未结订单阻止完成；不得误删多人团队资产。没有套餐保留期的数据不得伪称已清理，回收作业必须记录待处理状态。K10 完成与回收。
D4 通道实测与用途模板当前只知供应商已选择，运维须先核对密钥／发件身份／用途模板／签名的配置完整性；产品指定测试邮箱／手机号与发送预算，K6 实测记录送达证据。暂未实测不能标已验收。本次不会发送。P1 找回、手机号登录、管理员激活／重置开放。
D5 手机支付敏感确认需商户渠道真实联调及支付场景规则。短信码只确认发起敏感操作，支付成功仍来自验签＋金额核对＋原子入账，不由前端或码验证声明。K11 后续支付任务；不阻塞其他用户中心。
