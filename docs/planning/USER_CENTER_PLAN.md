## 一、功能优先级矩阵

### P0 核心功能（8 人天，MVP 必须）

| 功能点 | 工作量 | 用户痛点 | 技术依赖 | 备注 |
|--------|--------|----------|----------|------|
| **修改密码** | 2 人天 | 密码泄露无自救手段 | 无（复用 argon2id） | 旧密码验证 + 强度校验 + 修改后强制重登 |
| **邮箱验证** | 3 人天 | 防恶意注册、找回密码前提 | SMTP + verification_tokens 表 | 24h 有效链接，未验证用户功能受限 |
| **个人资料编辑** | 3 人天 | 用户身份感、团队协作 | OSS（头像上传） | 昵称/头像/时区 |
| **手机号绑定** | 6 人天 | **F19 依赖**、找回密码 | 阿里云 SMS + users.phone UNIQUE | 绑定/解绑 + 验证码 |
| **套餐与余额页** | 2 人天 | 用户需知道剩余次数 | 复用 billing.Service | 当前套餐 + 额度余额 + 到期时间 |

**P0 路径决策逻辑**：
- 无修改密码 = 用户被锁死（安全基础）
- 无邮箱验证 = 恶意注册泛滥 + 找回密码无门
- 无个人资料 = 团队协作识别度为 0
- 无手机号绑定 = F19 被阻塞 + 支付验证缺失
- 无余额页 = 用户焦虑"还能用几次"

### P1 重要功能（22 人天，提升体验）

| 功能点 | 工作量 | 价值 |
|--------|--------|------|
| 登录历史 | 4 人天 | 安全审计、异常检测 |
| 通知偏好 | 3 人天 | 减少打扰、提升打开率 |
| 微信绑定 | 5 人天 | 降低登录门槛、社交传播 |
| API Key 界面 | 4 人天 | 现有功能用户不可见 |
| 账单历史 | 2 人天 | 财务对账、报销凭证 |
| 发票申请 | 5 人天 | 企业客户刚需 |
| 成员管理 | 4 人天 | 3-10 人团队协作 |

### P2 延后功能（23+ 人天，长期价值）

- 双因素认证（5 人天）- 高安全客户需求明确后
- 企业微信/钉钉（8 人天/平台）- ToB 组织集成
- 站内通知（6 人天）- 运营数据支撑后
- 权限细化（10 人天）- RBAC 重构

## 二、界面结构设计

### 一级导航（左侧 Tab）

```
用户中心 (/settings)
├── 个人资料 [/settings/profile]
├── 账户安全 [/settings/security]
├── 绑定与集成 [/settings/connections]
├── 通知设置 [/settings/notifications]
├── API 管理 [/settings/api-keys]
├── 计费与订阅 [/settings/billing]
└── 团队管理 [/settings/team]（仅 tenant_admin 可见）
```

**设计原则**：
- 任务导向：用户直接看到"账户安全"而非"我要改密码"
- 独立计费入口：SaaS 核心变现点
- 角色隔离：团队管理仅 admin 可见

### 各 Tab 详细设计

#### 📋 个人资料 [Profile]

**布局**：
```
┌─────────────────────────────────────┐
│ 头像上传区（圆形，120×120px）          │
│   - 点击上传（jpg/png，<2MB）         │
│   - 初始头像：昵称首字母 Fallback      │
├─────────────────────────────────────┤
│ 表单字段（左对齐标签，右侧输入框）      │
│   · 昵称 [_____________]             │
│   · 邮箱  user@example.com (已验证)  │
│          [重新发送验证邮件]（未验证时）│
│   · 手机  +86 138****8888           │
│          [绑定手机号]（未绑定时）     │
│   · 时区  [Asia/Shanghai ▼]         │
├─────────────────────────────────────┤
│   [取消] [保存更改]                  │
└─────────────────────────────────────┘
```

**交互细节**：
- 昵称实时校验（2-20 字符，无特殊符号）
- 邮箱不可修改（改邮箱 = 改绑定，走独立流程）
- 手机号显示脱敏，点击跳转"绑定与集成"
- 保存后 Toast + 顶部导航栏同步更新头像

#### 🔗 绑定与集成 [Connections]

**手机号模块**：
```
┌─────────────────────────────────────┐
│ 手机号                                │
│   +86 138****8888  已绑定             │
│   绑定时间：2026-09-10                │
│   [解绑]                             │
└─────────────────────────────────────┘
```

**手机号绑定流程**（2 步 Modal）：
```
步骤 1/2：验证手机号
  手机号  [+86 ▼] [_______________]
          [发送验证码]
  验证码  [______]  60s 后可重新发送
  [上一步] [下一步]

步骤 2/2：确认绑定
  即将绑定手机号：138****8888
  ℹ️ 绑定后可用于：
    · 手机号登录
    · 找回密码
    · 支付验证
  [上一步] [确认绑定]
```

**解绑二次确认**（需输入登录密码）：
```
⚠️ 确认解绑手机号？
解绑后将无法使用手机号登录和找回密码
为了账户安全,请输入登录密码确认：
[············]
[取消] [确认解绑]
```

**第三方账号模块**：

```
│   │ [GitHub图标] GitHub 未绑定   │  │

│   └─────────────────────────────┘  │
└─────────────────────────────────────┘
```

**微信绑定流程**（扫码 Modal）：
```
┌─────────────────────────────────────┐
│ 微信扫码绑定                   [×]    │
├─────────────────────────────────────┤
│        ┌─────────────────┐         │
│        │   [微信二维码]   │         │
│        └─────────────────┘         │
│  请使用微信扫描上方二维码            │
│  二维码有效期 5 分钟                │
│  [刷新二维码]                       │
└─────────────────────────────────────┘
```

**交互细节**：
- 验证码 60s 倒计时，倒计时期间按钮置灰
- 验证码 6 位数字自动提交
- 解绑需输入登录密码（防会话劫持）
- 若手机号是唯一登录方式，禁止解绑并提示"请先验证邮箱或绑定其他登录方式"
- 微信绑定成功后同步微信头像（若用户未上传自定义头像）
- 第三方账号解绑前检查是否为唯一登录方式

## 五、待讨论问题

1. **头像上传 OSS 选择**：
   - 阿里云 OSS vs 七牛云 vs 本地存储（/opt/yuqing/uploads）
   - 建议：MVP 阶段用本地存储 + Gravatar 兜底，P1 再上 OSS

2. **邮箱验证"功能受限"范围**：
   - 方案 A：完全禁止创建分析（硬限制）
   - 方案 B：允许试用 1 次（体验优先）
   - 建议：方案 B，降低注册流失率

3. **手机号绑定与 F19 边界**：
   - F19 包含：手机号注册 + 手机号登录 + 短信验证码
   - 用户中心包含：手机号绑定/解绑 + 找回密码
   - 建议：两者协同开发，共用 users.phone + SMS 服务

4. **SMTP 服务选择**：
   - 阿里云邮件推送 vs SendGrid vs 自建 SMTP
   - 建议：阿里云邮件推送（国内到达率高）

5. **登录历史存储策略**：
   - 全量存储 vs 滚动窗口（保留最近 100 条）
   - 建议：滚动窗口 + 定期归档（降低存储成本）
