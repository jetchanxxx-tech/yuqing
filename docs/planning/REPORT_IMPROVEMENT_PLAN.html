一、复盘：为什么 BettaFish 机制没被真正融入

两次研究都做完了（22 项融合清单），交付却只落在表面。根因共六条：

#根因表现
1需求理解失败（产品主责）把「机制 + 角色」这条因果链降级成 22 项功能菜单，挑了 8 个最便宜的落地。表面项贡献约 20% 效果，内核（分维度深挖 + 角色分化 + 密度硬指标）贡献 80%，被默认排到 P2。
2研究结论从未进仓库22 项清单只存在于会话上下文；提交信息声称「详见审核报告附的研究结论」，但该附录实际不存在。后续任何会话都无法核对落地率。
3取舍标准是「能否一次冒烟验证」落地的 7 项全是 prompt 级改动（不动契约/迁移/前端）；需要动契约+迁移+前端的内核项被统一推到「以后」。
4验收标准是质感描述而非结构断言「输出像人话」不可证伪；「调用拓扑=N、产物 schema=X」可证伪。前者让跳过内核项成为合规交付。
542 次调用被整体否决，没做机制分解42 次里大头是「每段反思 ×3」的冗余；拆开后 7-10 次即可拿到八成收益。一次整体否决 = 100% 丢弃。
6成本不可观测 → 方案无法评估LLM 计量未接线，任何「增加调用」的方案算不出 ROI，被隐式否决且无记录。
结论：不是执行力问题，是产品定义失败 —— 没有用用户语言定义过「好报告」，也没有可证伪的验收口径。这次计划把两条都补上。

二、目标定义：好报告长什么样

用户拿到报告 30 秒内要能回答四问：发生了什么？大家怎么看？危险在哪？该做什么？

报告结构（重构后）

元信息 + 事件定性/行动建议徽章
① 执行摘要（150-250 字，≥3 个具体数字）
② 五维研判 —— 每维按五段骨架：核心发现 → 数据 → 代表性声音（逐字原声）→ 深入解读 → 趋势
   维度：背景与事件概述 / 热度与传播路径 / 公众情感与观点 / 群体与平台差异 / 深层原因与社会影响
③ 态势综合分析 —— 跨维度张力（情感同情但平台沉默、官方口径与民间感受背离）
④ 深层洞察与分阶段建议（立即 0-24h / 短期 1-3 天 / 中期）
⑤ 数据附录（情感/话题/平台对比/时间线/文档明细）

按 4 类 analysis_type 配场景模板（事件/品牌/竞品/行业），各自规定章节权重与篇幅下限。

关键转变：报告引擎从「从零写作」改为「编排 + 润色」—— 维度结论是组件，报告只写连接性叙述。从结构上杜绝二次概括（这是结论趋同的根源）。

三、角色体系（6 个）

角色实现方式职责
① 采集与证据官代码（非 LLM）文档去重/代表性采样/时间线/平台聚合 —— 确定性数字的唯一来源
② 分类员LLM ×1（temp=0）情感五级 + 置信度 + 话题聚类（附 doc_ids）
③ 维度分析员 ×5LLM ×5（temp=0.6，并发）各自专属人设：溯源专家 / 传播学者 / 民意研究员 / 社会分层学者 / 社会观察家 —— 输入证据底稿，输出五段骨架结论
④ 汇总研判师LLM ×1（temp=0.4）消费 5 维度结论 → 批判-重写摘要，重点找跨维度张力
⑤ 报告架构师规则（非 LLM）按场景模板 + 维度结论 → 章节大纲（省一次调用，确定性可测）
⑥ 编撰大师LLM ×1（temp=0.4）按 IR 撰写连接性叙述 + 渲染 HTML

四、分析机制（含反思循环的替代方案）

  • 5 维度：采纳，作为「深度研判」档（Pro 及以上套餐）。
  • 反思循环：我们没有在线检索能力，「带新数据多轮迭代」不可行。三级替代：
    1. 引用保真校验（0 次调用，性价比最高）：每条 quote.text 必须是源文档正文归一化后的子串，否则丢弃并记 warning；报告中的数字必须命中确定性统计或维度 data_points 白名单。直接打击幻觉，可单测。
    2. 维度交叉验证（确定性）：各维度数字与代码统计对账；trend 与时间线计算冲突时以代码为准（已有先例）。
    3. 冲突清单注入：不一致项喂给摘要与报告，让报告写出「张力」而不是抹平分歧。
  • 代表性文档采样：每维度按需抽 10-15 篇（热度维偏时间序列、群体维偏平台多样）—— 提升深挖质量同时控 token。
  • 证据底稿（EvidenceSheet）共享：分类阶段产出一次证据底稿（facts/quotes/numbers/timeline/actors），五个维度共享而非各自注入全量素材 —— 省 5 倍输入 token。

超时洞察 180s 硬编码洞察 ≥240s、报告 300s、管线总预算 660s；传输层超时改可配置

六、报告 IR（最小中间表示）

  • 块类型仅 7 种：heading / paragraph / bullets / quote / kpi_row / table / callout。
  • 表格只允许具名引用（platform_breakdown / sentiment_timeline / topic_table / risk_table / action_table），数据由代码聚合填入 —— 从结构上杜绝 LLM 编造表格数字。
  • 渲染器复用现有 _esc/_safe_url 转义与类型漂移防御；未知块跳过并记 warning。
  • 传输仍是 HTML（iframe sandbox 不变）；blocks 不入库不进契约，需要前端原生渲染时才加迁移。

七、开发计划（每阶段可独立部署）

P0阻断修复（0.5 天）—— 让半成品从「部署即崩」变为可用

  • 修 pipeline warning 语义反转：单维度失败当前会丢弃整份洞察（与降级设计相反）—— warn 非空但结果非空时仍 SetInsight，再 SetWarning
  • 补迁移 0005：ALTER TABLE analyses ADD COLUMN IF NOT EXISTS dimensions JSONB NOT NULL DEFAULT '[]'；部署顺序硬约束：先 migrate 再起新 server
  • 加每维度材料 token 预算（≤8k，超限按时间/相关性截断并回报截断数）
  • 验收：make test 全绿 + 真实 PG 契约测试 PASS + 生产 /result 出现 dimensions

P1报告消费维度 + 前端渲染（1 天）

  • report 引擎：按维度撰写章节（不再从聚合 JSON 重新概括）
  • 前端：新增「五维研判」Tab —— 五个折叠面板（默认展开核心发现；数据点 bullet、原声引用卡片、趋势标签）+ 底部「跨维度张力」区块；dimensions 为空时回落现有展示
  • 验收：E2E 新增五维 Tab 断言；npm run build 通过

P2IR + 骨架/篇幅 + 证据底稿（2 天）

  • 报告拆分两段：R1 骨架+篇幅（含 word_budget + rationale）→ R2 全章 IR 撰写
  • render_blocks 渲染器 + 引用保真校验（provenance 丢弃断言）+ 注入向量复测
  • 分类阶段产出共享证据底稿，五维路由取证据（省 5 倍输入）
  • 验收：块类型逐项渲染测试、未知块降级、引文命中率 ≥90%

P3一致性与计量（1 天）

  • 冲突清单注入 + max_tokens=4096 + usage 回传落 usage_events（成本可观测）
  • 并发闸门 3 + 429 指数退避重试；模型名弃用核查（上线前冒烟）
  • 验收：真实 DeepSeek 单次分析 <6 分钟；warning 可展示降级原因；/admin/usage 可见分析成本

八、验收标准（「不干燥、不趋同」可检验）

指标口径目标
引用密度每维 quotes 逐字命中原文≥90%，每维 ≥2 条
数字密度全报告可回溯数字≥10（摘要 ≥3）
维度差异两两维度结论 3-gram Jaccard<0.5（不趋同的结构性证明）
跨分析差异套话词表命中；5 份同模板不同事件摘要盲配套话 0 次；全可判别
盲评新旧报告 5 人评分（信息量/具体性/可读性）新版 ≥4 且显著高于旧版

流程验收：拿 3 个真实事件全部达标才算交付。
